# Design Guideline Anatomy

Derived from the local `awesome-design/design-md` collection and its stated DESIGN.md schema.

## Recurring Sections

The collection consistently documents:

- Overview / visual theme / atmosphere.
- Colors: brand/accent, surface, text, semantic, gradients, hairlines.
- Typography: font family, hierarchy, principles, substitutes.
- Layout: spacing scale, grid/container, whitespace philosophy.
- Elevation and depth.
- Shapes: border radius, image/photography geometry.
- Components: buttons, cards, inputs/forms, navigation, badges/tags, tabs, data tables, signature components.
- Do's and Don'ts.
- Responsive behavior: breakpoints, touch targets, collapsing strategy, image behavior.
- Iteration guidance and known gaps.

Observed heading frequency across the collection strongly favors hierarchy, spacing, typography principles, grid/container, buttons, breakpoints, touch targets, radius, components, and do/don't rules. Treat these as core sections, not extras.

## What Strong Guidelines Encompass

Corporate identity:

- Brand purpose, positioning, audience, values, personality, voice.
- Target customer segment and country/region context.
- Logo system: primary, secondary, mark, monochrome, reversed, favicon-safe, clear space, minimum size, misuse.
- Color system: primitives plus semantic roles for UI and communication.
- Typography system: hierarchy, weights, line heights, fallback and licensing notes.
- Imagery/iconography: subject matter, composition, treatment, grid, stroke/fill rules.

Corporate design:

- Layout system: spacing, grid, containers, whitespace rhythm.
- Shape system: radius scale, geometric rules, image geometry.
- Elevation system: shadows, borders, blur, surface layering.
- Component system: variants, states, anatomy, accessibility, token mapping.
- Responsive system: breakpoints, touch targets, collapse behavior, image behavior.
- Marketing assets: favicon, app icons, social avatar/banner, slide title, email/header/footer, ad templates.

## Practical Pattern

Write guidelines as design tokens plus rules:

- Token: exact value.
- Role: where it is used.
- Rationale: why it fits the brand.
- Constraint: where it must not be used.
- Example: correct usage.

Avoid vague taste language without implementation rules.
