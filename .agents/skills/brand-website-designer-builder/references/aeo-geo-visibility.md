# AEO/GEO visibility procedure

Apply for answer/generative-engine visibility audits and content work on existing or new sites, after the marketing bottleneck diagnosis justifies it (docs/archive/digital-marketing-optimization-plan.md §0). Load from maintenance.md for existing-site audits. Eligibility work never guarantees citations; quote only the binding evidence table in docs/archive/digital-marketing-optimization-plan.md §1.

Question mining: derive questions from actual audience evidence — People Also Ask APIs, Search Console question-regex pulls (`^(who|what|when|where|why|how|is|are|can|do|does|should)\b`), reviewed community sources — and produce a clustered question→URL map. Never invent question demand from model memory.

Answer structure: improve clarity for the reader using direct answers, comparisons and self-contained explanations where useful. There is no required capsule length or AI-specific writing style; test changes against the customer task, not a word-count rule. Inject named-source citations, verifiable statistics and real expert quotations where the owner can supply them. The owner verifies owner-only facts (prices, guarantees, firsthand claims) before publication; agent-recheckable facts are verified against current authoritative sources or an approved source record.

Schema: generate and validate markup for currently supported features only; markup must match visible facts. Google deprecated HowTo rich results (2023) and FAQ rich results (May 2026); do not present FAQ/HowTo markup as a rich-result or citation lever. Schema is hygiene, not a citation lever: repo-root `references/seo-rule-pack.md` (rules S1-S3 and evidence). Keep it for entity clarity and rich results.

Freshness: review when source facts, offers, customer questions or observed performance change. Record claim-level source/review dates; do not assert page-wide freshness from a calendar interval or bump dates without substantive verification.

Entity consistency: audit Organization/Person `sameAs`, profiles and directories; maintain Wikidata where eligible. Wikipedia requires earned notability — never force an article. Map which sources AI answers actually cite for the category's competitive prompts, so missed earned-media targets are visible rather than guessed.

First-party observation: inspect available authorized Google Search Console generative-AI performance data (link impressions) and Bing Webmaster Tools AI Performance (citation activity). Check actual property access and the Search generative AI inclusion setting, including inherited settings; this is separate from training policy. A dashboard/export does not establish API access. Preserve unavailable values as unknown even when exports convert placeholders to zero. Do not pool Google impressions, Bing citations, referral visits or configured API answers. When the owner must enable access or export data, prepare the exact account/property and date-range steps under the Marketing execution handoff in repo-root `references/marketing-execution.md`; do not stop unrelated technical/site work while access is pending. See [Google report](https://support.google.com/webmasters/answer/16984139), [inclusion control](https://support.google.com/webmasters/answer/16908024) and [Bing report](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview), checked 2026-09-21.

AI-answer observation: only when it answers a decision-relevant question, use the offline `scripts/monitoring/ai_answer_probe.py` with repo-root `references/ai-answer-recordings.md`. Require explicit subject, evidence-selected question text, surface/model/config/locale targets, provenance and error reasons. Use immutable new run directories and verified `--prior-run` input. Unknown compatibility, partial coverage and overlapping/reversed windows produce no eligible trends; excluded rows never affect selected results. Model output is observation, never customer-demand evidence. Live collection for declared API/Google targets is available through `scripts/monitoring/ai_answer_collect.py` under the same reference (cost cap, failed rows kept, reviewer judges recommendations); results are observations, never ranking claims. Start with the smallest panel that resolves the question, not a mandatory prompt count.

Measurement that needs no vendor tool: (1) a "how did you hear about us" field on the conversion form, with an AI-assistant option, is the most reliable attribution; (2) when analytics is active, an AI-referrer channel (chatgpt.com, perplexity, gemini.google.com, copilot.microsoft.com, claude.ai, deepseek.com), knowing several assistants send no referrer, so it undercounts; (3) server or CDN logs split training crawlers (GPTBot, Google-Extended, ClaudeBot) from retrieval crawlers (ChatGPT-User, OAI-SearchBot, PerplexityBot); a retrieval crawler returning to a page suggests it is used as a source; (4) 404s with steady referrals from assistants are hallucinated URLs: redirect them to the right page. Retrieval crawlers may not run JavaScript; server-render the content. Brand mentions without a link correlate with AI visibility more than links do in Ahrefs' 2025 brand study, so count unlinked editorial mentions as outcomes (link ledger `report`), not consolation prizes.

Message match: the AI-referrer analytics channel does not reveal the conversation or recommendation that sent a visit. Compare observed probe contexts or legitimately supplied conversations against landing pages as a diagnostic only — never as the actual context of individual AI-referred visits. Observable conversions and attribution limits follow the campaign measurement contract in `references/campaign-tracking.md`.

Crawler/access policy: describe each vendor control's real effect before implementing. `Google-Extended` is a product token (no HTTP user agent) covering training plus Gemini Apps grounding and Grounding with Google Search on Vertex AI; it cannot be observed in user-agent logs. OpenAI/Anthropic training and search/retrieval bots are independent. The owner selects per-vendor policy; also check CDN defaults (Cloudflare has blocked AI crawlers by default for new domains since Jul 2025). Never allow every AI bot by default. llms.txt: repo-root `references/seo-rule-pack.md` rules L1-L3.

Sources checked 2026-09-20: [Google AI features](https://developers.google.com/search/docs/appearance/ai-features), [Google-Extended](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers#google-extended), [HowTo/FAQ changes](https://developers.google.com/search/blog/2023/08/howto-faq-changes), [Search updates](https://developers.google.com/search/updates), [Ahrefs schema study](https://ahrefs.com/blog/schema-ai-citations/), [Ahrefs brand correlations](https://ahrefs.com/blog/ai-brand-visibility-correlations/). Refresh before consequential claims.

Decision output: apply repo-root `references/seo-rule-pack.md` (visibility decisions) and `references/marketing-execution.md` (owner-action contract). Return a bounded improvement queue with actual evidence, proposed changes, owner-only dependencies, acceptance checks and outcome review/stop rules. No action warranted is valid; local QA is not live uplift.

Current content guidance: [Google optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), checked 2026-09-21; no mandatory chunking or rewriting solely for AI.
