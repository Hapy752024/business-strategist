# Optional A/B testing with PostHog analysis

Only enter on explicit user request; record experiment selection separately from analytics selection. If analytics was declined, keep control-only and explain that measured PostHog analysis requires a new analytics decision. No automatic flags/account/traffic activation.

Declare one hypothesis/change, control/treatment, eligible consented audience, randomization unit, stable assignment/identity, allocation, exposure definition, primary conversion, attribution window, guardrails, minimum detectable effect, sample size/duration or chosen statistical stopping rule, exclusion rules and cleanup owner. Record these in the existing experiment manifest fields and linked experiment protocol. Do not promise an optimum or winner with inadequate traffic; report uncertainty, sample-ratio mismatch, contamination and consent-selection bias. Do not stop at the first significant result; follow the predeclared fixed-horizon or valid sequential stopping rule. Do not change metrics/splits mid-run without restarting the protocol.

Default existing fixture uses server-evaluated Vercel Flags and FlagValues with typed control/treatment. Preserve this path unless the user chooses PostHog assignment. For PostHog analysis of Vercel-assigned variants, explicitly configure PostHog custom exposure events and put the matching `$feature/<flag-key>` variant property on both exposure and metric events using the current experiments-without-feature-flags contract; a custom property on a conversion alone does not establish exposure. Alternatively choose a PostHog multivariate flag as the single assignment authority. Never independently randomize in both systems, client Math.random or localStorage assignment. Preview overrides are QA-only and excluded from analysis.

Render control without tracking for visitors who have not consented. After consent, ensure stable assignment and no flash/mismatch; server bootstrap or deliberate client transition must respect consent, cache isolation and privacy. Do not evaluate remote user-specific flags or create nonessential assignment identifiers before consent. Default to control on SDK/flag failure and record no exposure until the variant is actually displayed.

Send one exposure when the eligible visitor actually sees the variant, using consistent pseudonymous identity, experiment/flag key, variant and exposure time. Conversions use that same identity and variant, occur after exposure within the defined window, and are deduplicated on confirmed outcomes; no form PII. Handle reloads, SPA navigation, login identity transitions and withdrawals. Never replay pre-consent activity. Keep server credentials private and data in the user-selected PostHog EU project. Send only to an authorized destination; account/experiment creation remains an external action requiring authorization.

Test control/treatment forced in Preview, no-consent control/no traffic, stable assignment/reload, cache isolation, no flicker, exactly-once exposure, valid conversion attribution, direct thank-you visit, SDK failure, withdrawal races, exclusion of QA/bots and sample-ratio health. Confirm exposure and conversion ingestion in an authorized test project before production activation. Analysis handoff includes denominators, conversion counts/rates, effect/interval, stopping rule, data-quality findings and decision; do not automatically deploy a winner.

Follow current linked exposure/custom-assignment docs when implementing. Existing Vercel fixture is structural/runtime assignment coverage, not live PostHog analytics proof.
