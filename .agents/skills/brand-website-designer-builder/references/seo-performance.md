# Next.js SEO, LLM-EO and performance

Inspect installed package/lockfile and app or src/app location. New sites resolve stable versions; maintenance uses installed-version docs and separates upgrades. Do not copy canary APIs without verification. Prefer useful server-rendered/static content, narrow client boundaries, parallel independent fetches and deliberate caching/revalidation; never share-cache personalized data. Measure payloads before optimizing. Use font subsets, image dimensions/sizes and optimized served bytes; prioritize LCP media and defer nonessential JS subject to consent.

Use Metadata API/generateMetadata, metadataBase and file conventions. Verify actual dynamic/localized output, canonical and absolute OG URLs, meaningful headings and crawlable internal links. JSON-LD must represent visible facts; escape `<` in serialized JSON to prevent script termination. Never fabricate ratings/reviews/FAQs. Validate supported markup without promising rich results.

Production public pages should be indexable where intended; private/preview/thank-you routes should not. Preview authentication is stronger than robots. Do not block crawling and expect noindex to be read. Sitemaps include only canonical successful indexable URLs with accurate lastmod. Preserve redirects without chains. Check crawler-readable responses as well as hydrated DOM.

LLM-EO/GEO/AEO means discoverable, understandable, source-supported content: clear entities, useful sections, self-contained answers, visible authorship/sources and honest update dates. Keep human/crawler content consistent. Eligibility cannot guarantee citations. For audits and content procedure load `references/aeo-geo-visibility.md`; for commerce/agent readiness `references/deo-agent-readiness.md`. llms.txt is deprioritized (no measured impact in available studies; Google states it is unused); if used it requires an owner/update process and is never a launch prerequisite or substitute for SEO. Decide search versus training versus grounding access per vendor using current docs — `Google-Extended` is a product token that also controls Gemini/Vertex grounding, not a separate crawler — and never allow every AI bot by default.

Set budgets before building. Default mobile lab targets: LCP <=2500ms, CLS <=0.1, TBT <=200ms, Lighthouse performance >=90 and SEO >=95; record justified project-specific changes before acceptance. Run three production-build measurements with pinned tooling/device/network and median results, retain raw reports plus JS/image bytes and regression deltas. Scores are diagnostics, not complete SEO proof. Field p75 targets: LCP <=2.5s, INP <=200ms, CLS <=0.1 by mobile/desktop. New-site field data may be unknown: assign follow-up, never invent a field pass. Lab TBT does not prove INP.
