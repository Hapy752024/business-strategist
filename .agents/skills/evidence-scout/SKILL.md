# Evidence Scout

For a registered Business case, retain reviewed sources and counter-evidence in this skill's normal artifacts. Update that case's single `case_insights.md` after each coherent batch of reviewed findings, deep dives, answered founder questions or material corrections. Keep it a concise business recap, qualify provisional findings and disclose remaining questions in plain language. Do not wait for the whole research workflow to finish, and do not call a progress snapshot final delivery.
Bind the exact reviewed run and its claim ledger into the current insight publication. Render material VOC claims with direct original-source markers under repo-root `references/case-insights.md`; preserve source limitations and private-source references. Completed delivery also requires a separate review of the exact final document and consumed inputs. A provider failure is a coverage gap; continue applicable authorized fallbacks.
This skill tests the user’s stated idea or explains a customer segment’s pain, depending on the requested outcome. Similar companies at home or abroad are optional comparison evidence; importing one is not the default objective. Keep complementary research approaches in separate packets when they answer different questions, and deduplicate sources before synthesis.
## Success Criteria
- **Research quality:** every consequential finding has reviewed source-linked experiences, explicit scope and contrary cases; every requested locale/source has an honest coverage disposition. API success, record counts and tool-call quotas are not quality measures.
- **Qualitative:** users do not redirect mid-collection; provider failures are surfaced before evidence interpretation; evidence, interpretation, counter-evidence, and missing evidence are separated in every output.
## Workflow

1. For substantive query design, apply repo-root `references/research-query-calibration.md` (shared repository dependency). Read `references/workflow.md`, `references/provider-policy.md`, repo-root `references/voc-research-method.md`, and repo-root `references/research-execution.md` for substantive customer-needs work.
2. Initialize or reuse `projects/<topic-slug>/market_research/`.
3. Run capability lookup and provider doctor when routing matters, then use repository-root scripts.
4. Always run topic-led VOC discovery from the customer job/problem/trigger without requiring competitor names. For inferred vocabulary, new locales or poor retrieval, apply [pain-query calibration](references/pain-query-calibration.md): brainstorm wording and source locations → review the plan → execute exact candidate probes → review source experiences → refine and check fresh searches. Use short `--topic-keywords` for generated searches and `--query-plan` for exact probes. When forums or Facebook plausibly contain the target audience, use systematic community discovery with explicit locale pairs and per-seed forum/Group/Page lanes, signed metadata provenance, separate source-shape and fit checks, and evidence-bound promotion.
   For a registered case spanning several runs, register the entire decision, locales and capture set in the case manifest before final delivery. If a reviewed parent has a narrower target, preserve it as an adjacent study and use a v2 case assignment with a separate v4 target study; do not relabel the old source plan. After each batch run `scripts/evidence_scout/build_case_closeout.py` and reconcile every captured query separately, including zero-hit queries, plus applicable entity-feedback lanes. A bare not-applicable reason cannot waive a v4 lane; bind a reviewed original source or scoped discovery capture. Close via the assignment-aware completion check. Do not let a successful provider call or a small manually reviewed pack stand in for the whole case request.
5. Whenever verified competitors, substitutes or similar companies exist, also run entity-led customer-feedback analysis. Cover applicable independent review sites, Google business/location reviews, company Facebook/Instagram comments, Apple App Store reviews, Google Play reviews and external forums; keep company posts, replies and testimonials as supplier context. If entities are not known, mark this pass pending and start it after competitor discovery. Apply repo-root `references/customer-voice.md`, complete the executable source matrix, and validate separate topic/entity frames plus reviewed U-need and R-requirement mappings before synthesis.
6. Collection requires the authoritative current generation and separate discovery/review signing keys. Paid-API spending is authorized by the user; Facebook collection is only internally allowlisted and makes no platform-permission or terms-compliance claim. Private material must be user-supplied from legitimate access; never steal/share credentials, bypass access controls or use deceptive membership.
7. Inspect plans, raw outputs, evidence, irrelevant records, source-role counts, per-lane denominators, alerts, and gaps.
8. Paid API spend for customer evidence and voice-of-customer work is pre-authorized with no monetary cap; use and expand appropriate providers without a spend checkpoint. Query/sample bounds are for reproducibility, relevance and safe execution, not cost control. On `insufficient_credits`/`billing_required`, notify the user of lost coverage and the top-up route, continue with valid fallbacks where possible, and preserve the gap. If they report a top-up, re-validate and rerun before interpreting.
9. Block unsupported claims and invalid source attribution. Missing sources/geographies remain coverage gaps; publish only supported scoped findings, or an insufficient-evidence result.
10. After each coherent reviewed batch, update the current case insights through the validated publication flow, including while other source cells remain open. Before saying a substantive run is complete, execute the collection, research and, for a registered Business case, delivery checks in the research execution contract. A search batch's `passed` state means capture ran; it does not prove reviewed VOC or final delivery. Resume the first missing obligation and report partial work truthfully.
## Output

Return artifact paths, provider status, evidence and counter-evidence, confidence, gaps, and next test. Never treat attention as willingness to pay.
For segment sentiment/pain research, use discovery → provisional target hypothesis → narrowed validation; pass short `--segment-keywords` and semantically review target/adjacent/unresolved source membership. For chosen-idea or strategic continuation work, apply repo-root `references/research-coaching.md` (shared repository dependency).
