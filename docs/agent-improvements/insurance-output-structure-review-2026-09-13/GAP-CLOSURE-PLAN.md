## User-directed architecture amendment

The user refined the intended layout during closure work. New projects use an umbrella controller with explicit `controller_kind: umbrella` and layout version 3. It registers `business/`, `branding/`, `digital-assets/website/`, and `digital-assets/others/`. Each starts independently; sequencing and handoffs are opt-in. `digital-assets/` is only an organizational folder, with no extra stage machine or approval gate. Business owns research, investigated cases, feasibility, economics, selection, strategy/business plan, GTM and optional marketing/operations.

The existing version-2 case controller runs inside Business with the original project identity, not the common directory name “business”. The umbrella owns publication for Branding and Digital Assets. Owners have disjoint write paths; Business has its own evolution log, while design/digital publications use the umbrella evolution log and snapshots. Current documents link to those histories. No live research is moved. Existing legacy and version-2 projects retain their old paths; ordinary standalone design remains available there.

Acceptance additions: independently start each subproject first; normal brand and website commands succeed without Business; nested business discovery/resume and routing resolve correctly; Business → Branding handoffs validate one source authority and publish through the destination authority; stale source and destination conflicts block publication; case selection never changes from design work; root navigation contains no duplicated stage authority.

Numerical checking is bounded to authored model-derived claims, including multi-line values and comparison summaries. It does not establish the truth of arbitrary prose or prohibit dated/source-attributed market observations. Missing downside and sensitivity ranges remain explicitly unresolved while provisional arithmetic is still available.
