## One log: independently assessed recommendation

**Use one project human evolution timeline in either architecture.** Physical case storage is not a reason to maintain separate authoritative diaries. A cross-case reversal should be discoverable once, tagged with every affected scope.

Canonical `history/decisions/<event-id>.md` records own when/what/why and before/after references. Machine manifest events own operational transitions and reference that decision; they must not repeat an editable explanation. The timeline is a derived entrypoint; filtered case views are optional projections. Run/provider logs and immutable snapshots serve different purposes and remain separate. This is one logical human history, not a demand to put every record in one giant file.

Separate authoritative logs become reasonable only with explicitly independent operating teams/ownership. Merely having many variants calls for filtering, not duplicated explanations. Current outputs may contain citations, uncertainty and the current next action; they must exclude chronological update blocks and superseded recommendations. “Current” is freshness, never approval.
