# Website module

Owns marketing website implementation, content fidelity and rendered-task quality. It can start from its own brief without completed Business or Branding work. Imported brand and Business inputs retain their source, revision, digest, applicability and unresolved limits. Review the rendered key user task and verify published claims against approved evidence.

For a selected website conversion task, test the complete form-to-destination flow where the authorized environment permits. A local fixture or client-side confirmation is not proof of real lead receipt. If destination access belongs to the owner, provide the exact setup/test steps and continue independent page and technical checks.

## Focused technical helpers

The website builder remains the owner of complete website delivery. Use the explicit checked routes `stripe-best-practices` for Stripe integration, `security-review` for security assessment, `webapp-testing` for local browser checks, and `pre-release-regression` for release coverage. Select the actual target application and pass its instructions and scope; these helpers do not assume a shared application stack.

Run `python3 scripts/route_workflow.py "<bounded task>" --intent <route-id> --task-scope focused --check-skill <skill-name>` before dispatch, retaining project and case context when applicable. Existing Business gates and external-action approvals still apply. A payment helper does not authorize live charges, a launch or deployment.
